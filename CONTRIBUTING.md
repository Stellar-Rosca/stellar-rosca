# Contributing to Stellar ROSCA

We welcome contributions to the Stellar ROSCA platform! This guide will help you get started.

## 🤝 How to Contribute

### Reporting Bugs
- Use the GitHub issue tracker
- Provide detailed information about the bug
- Include steps to reproduce
- Add screenshots if applicable

### Suggesting Features
- Open an issue with the "enhancement" label
- Describe the feature and its use case
- Explain why it would be valuable

### Submitting Pull Requests
1. Fork the repository
2. Create a feature branch
3. Make your changes
4. Add tests if applicable
5. Update documentation
6. Submit a pull request

## 🛠️ Development Workflow

### Setting Up Development Environment
1. Clone your fork
2. Install dependencies for all components
3. Set up your development environment
4. Run tests to ensure everything works

### Code Style
- Follow Rust conventions for smart contract code
- Use ESLint and Prettier for JavaScript/React code
- Write clear, descriptive comments
- Keep functions small and focused

### Testing
- Write tests for new features
- Ensure all tests pass
- Add integration tests where appropriate
- Test on both testnet and local environments

## 📝 Guidelines

### Smart Contract Changes
- Test thoroughly with various scenarios
- Consider gas optimization
- Update documentation
- Add appropriate events

### Backend Changes
- Follow RESTful conventions
- Add proper error handling
- Update API documentation
- Add logging for debugging

### Frontend Changes
- Ensure responsive design
- Test wallet integration
- Update component documentation
- Consider accessibility

## 🎯 Areas for Contribution

### High Priority
- Bug fixes and stability improvements
- Security enhancements
- Performance optimizations
- Documentation improvements

### Medium Priority
- Additional wallet integrations
- Enhanced UI/UX features
- Mobile responsiveness
- Internationalization

### Low Priority
- Advanced analytics
- Social features
- Gamification elements
- Custom themes

## 📋 Pull Request Template

### Description
Brief description of changes

### Type of Change
- [ ] Bug fix
- [ ] New feature
- [ ] Breaking change
- [ ] Documentation update

### Testing
- [ ] Tests added/updated
- [ ] All tests pass
- [ ] Manual testing completed

### Checklist
- [ ] Code follows project style guidelines
- [ ] Self-review completed
- [ ] Documentation updated
- [ ] No breaking changes (or documented)
